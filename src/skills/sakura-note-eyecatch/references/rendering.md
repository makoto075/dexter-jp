# 再現用レンダラー

## 入力の準備

Python 3とPillow 10以上を使用する。設定例を案件の `cover.json` にコピーしてから編集する。画像・フォントは同梱していない。例の写真パスは実在する利用可能な写真に置き換える。

| 設定 | 意味・制約 |
|---|---|
| source_image | 横長写真。EXIFの向きを適用した後も横長であること。元画像は変更しない |
| output_basename | 拡張子なしの出力名。例 `output/sakura-note-20261108-v01`。既存名は上書きできない |
| font_bold / font_regular | 実在し、必要な日本語を収録するフォントファイル。明朝の実例はNotoSerifJP-VF.ttf |
| font_family | SVG向けのフォント名。実際のフォントと一致させる |
| brand / label | 「さくら」と記事に合う小見出し。ラベルは省略可能 |
| headline | 空でない文字列が厳密に2つ。長さは実際の描画幅で判断 |
| product / subtitle | 補足。不要なら空文字。商品や資格を創作しない |
| label_color / product_color / subtitle_color | #RRGGBB形式 |
| mask_rgb | RGB整数3つ、各0〜255 |
| mask_opacity_stops | [横位置, 不透明度]の組。各値0〜1、横位置は昇順で重複なし、両端0と1を含む |
| crop_center | クロップ中心のx,y、各0〜1 |

パスはJSONのあるディレクトリを基準に解決する。絶対パスも使用できる。フルセットフォントの存在と利用条件を確認する。別PCではWindowsのフォントパスをそのまま使わない。

## 実行

ユーザー指定・環境の画像編集規則がコードによる再現を許可する場合に使用する。各ファイルを相対パスどおり保存し、Skillフォルダから実行するPowerShell例：

```powershell
$env:PYTHONIOENCODING='utf-8'
$env:PYTHONUTF8='1'
python -X utf8 'scripts/render_sakura_cover_mincho.py' 'cover.json'
```

成功時は標準出力に出力名、1280×670のサイズ、文字ごとの最小コントラスト、補助クロップ量がJSONで出る。これを案件のQA記録に保存し、別途目視結果を追記する。スクリプトはQA.jsonを自動保存しない。UTF-8・BOMなしで記録する。

## 出力と調整

- PNG、JPG、WebP、参照SVG、320×168 PNG、160×84 PNG、1.618比率の中央クロッププレビューを作る。
- noteへの引き渡しはPNG/JPGを使用する。SVGは背景のみ埋め込み、フォントは外部参照なので正本にしない。
- 文字の左端は136px。見出しは82pxでy=206/310、右端820pxまで。長い見出しを自動縮小せずエラーにするので、まず文言を短くする。
- ラベル26px、補足32px/25px、ブランド26px。見出しは白、ブランドは砂色。JSONで変更できない配置・色を変える場合は元スクリプトを保持して案件側の派生版を作り、再検証する。
- 写真はEXIFの向きを反映してRGBへ変換し、出力には元のEXIFを明示コピーしない。元画像は保存し直さない。
- 途中で失敗した場合は成果物の有無を確認する。再実行には新しいバージョン名を使い、途中成果物を完成品として渡さない。

## 完了の根拠

スクリプト成功に加えて、実際の画像の日本語と記事との整合を目視する。コントラスト値は今回の実行値を使う。過去のQA数値を新しい画像の検証結果として流用しない。投稿画面を確認していなければ、noteでの実表示は未確認とする。

MCPから手順を取得できても、写真への権限・Python実行環境・画像編集ツールが提供されるわけではない。利用先での実行可否を分けて報告する。
